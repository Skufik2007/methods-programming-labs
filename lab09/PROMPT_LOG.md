## Записи по заданиям варианта 3

### 1. Средн. №3 (Go) — скомпилировать Go-программу в бинарь и вызвать её из Python через subprocess

| | |
|---|---|
| **Задача для AI** | Go-программа принимает данные от Python и возвращает результат; Python вызывает скомпилированный бинарь как подпроцесс. |
| **Что предложил AI** | Обмен JSON через stdin/stdout. Ошибка возвращается JSON-объектом `{"error": …}` с кодом выхода 1. Переполнение `int64` проверяется явно. В Python — обёртка с тайм-аутом, собственным исключением и автоматической сборкой бинаря. |
| **Принято** | Протокол, обработка ошибок, тесты Go и интеграционные тесты Python. |
| **Изменено после проверки** | Автосборка смотрела на время изменения файлов и не учла бы общие пакеты. Заменено на вызов `go build`, у которого есть собственный кеш. |
| **Оставлено осознанно** | Ошибки пишутся в stdout, а не в stderr: у вызывающей стороны один машиночитаемый канал, а код выхода отличает успех от ошибки. Обоснование вынесено в README. |

### 2. Средн. №5 (Go) — TCP-сервер на Go, к которому подключается Python-клиент

| | |
|---|---|
| **Задача для AI** | TCP-сервер на Go с несколькими командами и клиент на Python. |
| **Что предложил AI** | Построчный JSON-протокол, горутина на каждое соединение, учёт открытых соединений для корректной остановки, лимит длины строки, тайм-аут простоя. Клиент на Python — контекстный менеджер. Тест на 10 одновременных клиентов в Go и 20 в Python. |
| **Принято** | Архитектура сервера и протокол. |
| **Изменено после проверки** | Добавлен тайм-аут на запись (`SetWriteDeadline`): зависший клиент больше не блокирует горутину. Ошибки установки тайм-аутов обрабатываются. Закрытие по тайм-ауту простоя логируется как штатное событие, а не как ошибка. |
| **Не принято** | Замечание «клиент не вычитывает ответ на `quit`». Проверка показала, что метод `request()` уже читает ответ, поэтому поведение не менялось, а в код добавлен поясняющий комментарий. |

### 3. Средн. №8 (Rust) — собрать модуль с Maturin и импортировать в Python

| | |
|---|---|
| **Задача для AI** | Python-модуль на Rust (PyO3), сборка Maturin, использование из Python. |
| **Что предложил AI** | Вся математика — в обычных Rust-функциях, покрытых `cargo test`; `#[pyfunction]` только переводят типы и ошибки (переполнение → `OverflowError`). Тяжёлые функции отпускают GIL. Сборка abi3 даёт одно колесо для Python 3.9+. |
| **Принято** | Архитектура модуля и набор функций (`sum_squares`, `count_primes`, `primes`, `is_prime`). |
| **Изменено после проверки** | Решето на `Vec<bool>` занимало до 1 ГБ памяти — заменено битовым решетом по нечётным числам (~60 МБ). Ускорение относительно Python выросло с ×2.5 до ×8.9. Добавлены тесты граничных случаев. |

### 4. Повыш. №3 — сборка Rust-модуля в CI/CD и публикация на PyPI

| | |
|---|---|
| **Задача для AI** | Автоматическая сборка колёс в GitHub Actions и публикация на PyPI. |
| **Что предложил AI** | Сборка для Linux, Windows и macOS, проверка установки колеса, sdist. Публикация по тегу `v*` через Trusted Publishing (OIDC), без хранения токенов в секретах. |
| **Моё решение и моя часть** | Формулировка задания допускала только *настройку* публикации, но попытка сдачи одна. Поэтому я решил, что пакет должен быть опубликован по-настоящему: это лучшее доказательство того, что конвейер работает. Аккаунт на PyPI и доверенного издателя (Trusted Publisher) для репозитория я настроил сам. |
| **Результат** | Пакет [`fastmath-chetverikov` 0.1.0](https://pypi.org/project/fastmath-chetverikov/) опубликован. Установка `pip install fastmath-chetverikov` проверена в чистом окружении. |
| **Изменено после проверки** | Перед публикацией версия тега сверяется с `pyproject.toml` и `Cargo.toml`. Actions обновлены до актуальных версий (были предупреждения о Node 20). |
| **Оставлено осознанно** | Колёса собираются и при push в `main`: так видно, что релиз соберётся, ещё до постановки тега. Причина записана в комментарии workflow. |
