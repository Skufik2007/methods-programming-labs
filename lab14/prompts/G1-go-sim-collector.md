### Что сделать

Go-модуль `go/` (`module github.com/Skufik2007/methods-programming-lab14/go`, `go 1.27`),
логи `log/slog` JSON.

1. **`go/cmd/sensorsim`** + пакет `go/internal/sim` — эмулятор по разделу 3:
   детерминированная генерация показания `(SEED, device_id, k)` без хранения (хэш → PRNG),
   реалистичные значения с плавным дрейфом (не белый шум), клинические эпизоды (2.3),
   намеренные дефекты (2.2) с долями из окружения, `LATENCY_MS` с джиттером, `/metrics`.
2. **`go/internal/collector`** + **`go/cmd/collector`** — ядро сборщика по разделу 4:
   - пул горутин опрашивает устройства (`after_seq` → чекпоинт), канал с буфером, пакетная
     запись по `BATCH_SIZE`/`FLUSH_INTERVAL`;
   - **tumbling-окна** (пакет `go/internal/window`): агрегат раздела 2.4, закрытие по
     `window_end + WINDOW_LATENESS` по часам сборщика, счётчик `late_dropped`, режим
     `EMIT=raw|agg|both`; валидация диапазонов для поля `invalid` — по таблице раздела 2;
   - **стоки за интерфейсом** `Sink` (`WriteRaw`, `WriteAgg`, `Flush`, `Close`) — сделай
     только `files` (JSONL по разделу 4); NATS и Flight добавит следующий промпт, поэтому
     интерфейс и регистрация стоков должны позволять добавить их без переделки ядра;
   - **источник устройств и чекпоинты за интерфейсами**: `Assigner` (какие устройства мои;
     сейчас — статический: все устройства эмулятора или список из окружения) и
     `CheckpointStore` (сейчас — в памяти и файл `OUT_DIR/checkpoints.json`). Чекпоинт
     обновляется только после успешного `Flush` всех стоков;
   - graceful shutdown по разделу 4 (порядок шагов важен); `/metrics` и `/status`;
   - часы инжектируются (окна и сброс по таймеру должны тестироваться без `time.Sleep`).
3. Конфигурация — переменные окружения из контракта, разбор в отдельном пакете с проверкой
   значений (понятная ошибка, код выхода 2).

### Ограничения

- Только стандартная библиотека (+ `github.com/google/uuid`, если нужен). Тесты не пиши —
  их напишет другая модель, но код должен быть тестируемым.
- Go в `D:\dev\go\bin` (`export PATH="/d/dev/go/bin:$PATH"`). В конце: `go mod tidy`,
  `go build ./...`, `go vet ./...`, `gofmt -l .` пусто. Затем **один** короткий дымовой
  запуск: эмулятор (`DEVICES=20 LATENCY_MS=20`) + сборщик на 10 с в каталог в
  `%TEMP%`, проверь, что появились raw и agg JSONL и сборщик корректно завершился по
  сигналу. На Windows послать SIGINT фоновому процессу из скрипта трудно, поэтому добавь
  флаг `-duration` (по истечении — тот же путь graceful shutdown, что и по сигналу) и
  проверь завершение через него. Если после двух попыток что-то не работает — не продолжай
  отлаживать, опиши проблему в ответе.
- Не делай git-коммитов. Файлы создавай инструментом Write (кириллица в путях ломается в
  heredoc Git Bash). Комментарии на русском, только к неочевидному.

## Почему так

- Ядро и стоки разделены, чтобы etcd/NATS/Flight (G2) добавились без переделки и чтобы
  генератор работал над узкой задачей (экономия токенов — договорённость после ЛР №13).
- Детерминированный эмулятор без хранения: одинаковые данные в CI, бенчмарках и тестах.
- Лимит на отладку — 2 попытки: в ЛР №13 длинные циклы отладки генераторов съедали больше
  всего токенов.

Допущения генератора:

- Дубликат — повтор `seq = after_seq` первым в ответе (вне `limit`); вне диапазона — `999` и т.п.;
