Модель-генератор: Claude Haiku 5.5, effort low (подагент, не видит ход работы).

## Промпт

Ты — инженер по тестированию на Go. Модуль `go/` в
`D:\6 семестр\Методы программирования\lab14`, контракт — `docs/ARCHITECTURE.md`
(разделы 2–6). Напиши тесты на стандартном `testing` (табличные, `t.Run`). **Ожидания бери
из контракта, а не из текущего поведения кода.**

### Что покрыть (по пакету — отдельный файл `*_test.go`)

1. `internal/sim` — детерминизм (один `SEED` → одинаковые показания), монотонность `seq`,
   доли дефектов в пределах допуска на 20 000 показаний, `after_seq`/`limit` в HTTP через
   `httptest`.
2. `internal/window` — границы окна полуоткрытые, выравнивание по эпохе, закрытие по
   `window_end + lateness` на фейковых часах (`internal/clock`), `late_dropped`, агрегаты
   (`count`, `invalid`, `sum/min/max/mean/last`), окно без валидных значений.
3. `internal/collector` — пакетная запись по размеру и по таймеру (фейковые часы), чекпоинт
   двигается только после успешного `Flush` всех стоков (сток-заглушка, который падает),
   порядок graceful shutdown (буфер сброшен, окна закрыты, чекпоинты записаны).
4. `internal/coord` — HRW: детерминизм, равномерность (≥ 35% на каждого из двух при 1000
   устройствах), минимальное перемещение при добавлении члена; etcd-часть — со встроенным
   etcd (`go.etcd.io/etcd/server/v3/embed`, `t.TempDir()`, случайные порты): членство под
   lease, исчезновение ключа после `Close`, чекпоинт не откатывается назад.
5. `internal/sinks/files` — формат JSONL байт-в-байт по контракту (поля, `72.0`, `ts` с мс).
6. `internal/sinks/flightsink` — конвертация в Arrow: схема строго по разделу 6, словари,
   батчи по 8192, nullable-поля; `DoGet` через Flight-клиент на случайном порту.
7. `internal/sinks/natssink` — со встроенным `nats-server/v2` (JetStream, `t.TempDir()`):
   субъекты, `Nats-Msg-Id`, дедупликация повторной публикации.
8. `internal/config` — ошибки конфигурации.

### Ограничения

- Код приложения **не меняй**. Ошибку кода — оставь падающим тестом с комментарием
  `// НАХОДКА:` и перечисли в ответе.
- Тестовые зависимости — `go get`, `go mod tidy`. Go в `D:\dev\go\bin`.
- В конце один раз: `go vet ./...`, `go test -cover ./...` (без `-race`: на Windows нет
  cgo). Если тест не удаётся написать за две попытки — пропусти его и упомяни в ответе;
  **не** гоняй цикл «запустил → поправил» больше двух раз на файл.
- Не трогай `python/`, `rust/`. Не делай git-коммитов. Файлы — инструментом Write.
