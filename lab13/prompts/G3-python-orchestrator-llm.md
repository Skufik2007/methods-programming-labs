### Что сделать

Python 3.12, пакет `mas` в корне репозитория, `pyproject.toml` в корне (setuptools,
зависимости: `nats-py`, `pydantic>=2.7`, `pydantic-settings`, `httpx`,
`opentelemetry-api`, `opentelemetry-sdk`, `opentelemetry-exporter-otlp-proto-http`,
`fastapi`, `uvicorn[standard]`, `jinja2`, `redis>=5`; dev: `pytest`, `pytest-asyncio`,
`pytest-cov`, `ruff`). Настройки ruff и pytest возьми из
`D:\6 семестр\Методы программирования\lab12\pyproject.toml` (правила E,F,W,I,UP,B,S,ASYNC;
`asyncio_mode = "auto"`; coverage с `branch = true`), приспособив к пакету `mas`.

1. `mas/common/` — общее:
   - настройки через pydantic-settings из окружения (`NATS_URL`, `OTEL_EXPORTER_OTLP_ENDPOINT`,
     `OTEL_SDK_DISABLED`, `LOG_LEVEL`, `LOG_FILE`, таймауты шагов, `OLLAMA_URL`, `LLM_MODE`);
   - pydantic-модели всех сообщений контракта (задача, результат, обращение с
     ограничениями из 4.3, выходы шагов, ставка, heartbeat, событие);
   - шина: подключение, идемпотентное создание потока `TASKS` и консьюмеров
     `step-<step>`, публикация задачи с заголовками `traceparent` и `Nats-Msg-Id`,
     публикация событий и heartbeat;
   - телеметрия: TracerProvider с OTLP/HTTP, inject/extract `traceparent` для заголовков
     nats-py; без Jaeger всё работает;
   - логирование: уровни INFO/ERROR, вывод в консоль и в файл (`LOG_FILE`), JSON-строки;
   - разбор файла роли (раздел 8 контракта): разделы Markdown + YAML после `## Параметры`
     (используй `pyyaml` — добавь в зависимости).
   Никаких подключений и глобального состояния при импорте модулей: только фабрики и
   явный `connect()`/`close()`.
2. `mas/orchestrator/` — оркестратор:
   - класс `Orchestrator` (async): `start()`/`stop()`, подписка на `results.>` и
     `agents.heartbeat`; `start_case(case) -> run_id` запускает цепочку фоновой задачей;
     `submit_feedback(appointment_id, patient_id, rating, text) -> run_id` — короткая
     цепочка отзыва (раздел 2);
   - цепочка из раздела 2: выход шага → `payload.previous` следующего, `payload.case` —
     исходное обращение; `emergency` останавливает цепочку (`stopped`);
   - повторы и таймауты по разделу 5 (до 3 попыток, таймаут на шаг из настроек, повтор
     только при таймауте или `retryable`), устаревшие результаты игнорируются;
   - аукцион по разделу 6: nats-py `request()` возвращает только первый ответ, поэтому
     собери ставки сам — свой inbox, публикация с `reply`, сбор 500 мс; выбор
     победителя строго по правилу контракта (вынеси в чистую функцию); бронь у
     победителя через `agent.<id>.book`; при `slot_taken` — новый раунд, до 3;
   - хранилище запусков в памяти (ограниченное, последние 500) за интерфейсом: запуск
     с шагами (статус, попытки, агент, выход, ошибка, время начала/конца), `trace_id`;
     возможность подписаться на изменения (для дашборда);
   - реестр агентов по heartbeat (в сети, если моложе 15 с) и метрики-счётчики (запуски
     по статусам, задачи, повторы, таймауты);
   - события журнала `published`, `retry`, `timeout`, `stopped`, `won` (раздел 10);
   - трасса: корневой спан `pipeline.run` на запуск, дочерние `step <name>`, контекст
     уходит в `traceparent` задач;
   - CLI `python -m mas.orchestrator demo --cases N [--concurrency K]`: отправляет N
     демо-обращений (набор правдоподобных жалоб, в том числе одна с красным флагом) и
     печатает итоговую таблицу статусов — для демонстрации и нагрузки при масштабировании.
3. `mas/llm_agent/` — LLM-агент (задание 7), процесс `python -m mas.llm_agent --role roles/intake.md`:
   - роли `roles/intake.md` (шаг `intake`: свободный текст → симптомы, специальность,
     красные флаги, резюме) и `roles/feedback_reply.md` (шаг `feedback_reply`: вежливый
     ответ пациенту на негативный отзыв, без медицинских назначений). Системный промпт
     собирается из разделов роли; параметры модели — в YAML роли;
   - читает задачи своего шага из JetStream (`step-<step>`), отвечает по контракту,
     heartbeat с `lang: "python"`, события, спан `process <step>` с родителем из
     `traceparent`;
   - клиент Ollama: асинхронный `httpx`, `POST /api/chat`, `format: "json"` для intake,
     `options`: `temperature` 0.2, `num_predict`, `repeat_penalty` 1.1 (маленькие модели
     зацикливаются), таймаут. За основу возьми клиент из
     `D:\6 семестр\Методы программирования\lab12\.github\scripts\ai_review.py`
     (там urllib — перепиши на httpx async, источник укажи в docstring);
   - защита от prompt injection: текст пациента — внутри явных разделителей, разделители
     во входе вырезаются, в промпте сказано считать его данными; ответ валидируется
     pydantic-схемой, специальность — только из справочника;
   - `LLM_MODE=fallback` или любая ошибка модели (таймаут, невалидный JSON, нет сервера) →
     правила по ключевым словам, `source: "fallback"`, причина — в событии. Agent не
     падает и не ретраит вечно.

## Почему так

- Сбор ставок вручную — потому что `request()` в nats-py ждёт один ответ, а аукциону
  нужны все; выбор победителя — чистая функция, чтобы проверить правило тестами.
- Fallback без LLM нужен и для CI (там нет Ollama), и для надёжности: недоступность модели
  не должна останавливать запись пациентов.
- Подключения только через фабрики — учтено замечание бота по ЛР №12 (engine при импорте).
