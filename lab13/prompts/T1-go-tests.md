## Промпт

Ты — инженер по тестированию на Go. В репозитории `D:\6 семестр\Методы программирования\lab13`
есть Go-модуль `agents/` (универсальный агент мультиагентной системы и автомасштабировщик).
Контракт системы — `docs/ARCHITECTURE.md`, роли агентов — `roles/*.md`. Прочитай контракт и
код пакетов `agents/internal/*`, затем напиши модульные и интеграционные тесты на стандартном
пакете `testing` (табличные тесты, `t.Run`, `t.Parallel()` где безопасно).

### Что покрыть

1. `role` — разбор файлов роли: все реальные `roles/*.md` разбираются; ошибки — нет блока
   `## Параметры`, битый YAML, неизвестный `kind`, нет `step`.
2. `schedule` — сетка слотов, полуоткрытые интервалы (касание границ — не пересечение),
   нерабочий день, последний неполный слот отбрасывается, прошедшие слоты не предлагаются,
   местное время `Europe/Moscow`.
3. `triage` — каждое правило: красные флаги из текста и из `previous.red_flags` (LLM может
   добавить, но не убрать), регистр и ё/е, `urgent` по ключевым словам, возраст (< 1 года,
   75+), специальность вне справочника → `therapist`, приоритет `preferred_specialty` при
   `routine`, `max_wait_hours` по уровням.
4. `booking` — формула `cost` по разделу 6 контракта (проверь числом), `eligible=false` с
   причинами, исключение по `exclude_agents`, бронь через хранилище в памяти, повторная бронь
   того же слота → `slot_taken`, проверки слота (прошлое, вне смены, не на сетке).
5. `reminder`, `feedback`, `dispatch` — расписание напоминаний (пропуск прошедших смещений,
   одно «сейчас», демо-задержка), повторная обработка той же записи не создаёт дублей,
   два диспетчера на одном хранилище не отправляют один элемент дважды, анализ отзыва
   (оценки 1..5 и вне диапазона, тональность при 3, темы, `nps_bucket`), статистика.
6. `store` — реализация Redis на `github.com/alicebob/miniredis/v2` (те же сценарии, что у
   Memory: `SETNX`, `ZADD`/`ZRANGEBYSCORE`/`ZREM`, `HINCRBY`).
7. `autoscale` — политика `Desired` (рост сразу, уменьшение только после `cooldown`,
   границы `min`/`max`, нулевой backlog), цикл `Reconcile` с фейковыми наблюдателем и
   бэкендом (запуск/остановка нужного числа, отсутствие консьюмера), разбор конфигов
   `deploy/autoscaler.*.yaml`; бэкенд docker — через `httptest`-сервер, имитирующий Docker
   Engine API (create/start/stop/remove/list с метками).
8. `bus` + `cmd/agent` — интеграция с **встроенным** NATS-сервером
   (`github.com/nats-io/nats-server/v2/server`, JetStream во временном каталоге `t.TempDir()`,
   случайный порт): агент триажа получает задачу из `tasks.triage`, публикует результат в
   `results.<run_id>` с тем же trace_id в `traceparent`, шлёт heartbeat и события; некорректный
   JSON задачи не роняет агента; два экземпляра на одном консьюмере делят задачи (обе
   получают хотя бы одну из 20); аукцион: два агента записи отвечают ставками на
   `auction.booking`, бронь через `agent.<id>.book`.

### Ограничения

- Код приложения **не меняй**. Если тест выявил ошибку в коде — оставь тест падающим,
  пометь комментарием `// НАХОДКА:` с описанием и перечисли такие тесты в ответе. Не
  подгоняй ожидания под ошибочное поведение: ожидания бери из контракта и ролей.
- Тестовые зависимости (`miniredis`, `nats-server`) добавь в `go.mod` (`go get`, `go mod tidy`).
- Go в `D:\dev\go\bin` (`export PATH="/d/dev/go/bin:$PATH"`). Сеть нестабильна — повторяй
  скачивание. Перед завершением: `go vet ./...`, `go test -race ./...` (если `-race`
  недоступен на Windows без cgo — без него, напиши об этом), `go test -cover ./...` — приведи
  покрытие по пакетам. Цель — не ниже 80% для пакетов с логикой.
- В Git Bash кириллица в путях внутри heredoc может ломаться — создавай файлы инструментом
  Write. Не делай git-коммитов. Комментарии в тестах — на русском, к неочевидному.

## Почему так

- Ожидания из контракта, а не из кода: иначе тесты закрепят ошибки генератора G1.
- Встроенный nats-server — интеграционные тесты без Docker и внешних процессов, работают и
  локально, и в CI.
