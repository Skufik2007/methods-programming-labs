# G4 — веб-панель мониторинга агентов (задания 8, 3)

Модель-генератор: Claude Sonnet 5.5 (подагент, не видит ход работы).

## Промпт

Ты — опытный Python-разработчик веб-приложений. В репозитории
`D:\6 семестр\Методы программирования\lab13` есть мультиагентная система поддержки
пациентов: контракт — `docs/ARCHITECTURE.md`, оркестратор — `mas/orchestrator`, общие
модели и шина — `mas/common`. Прочитай контракт и публичный API оркестратора. Сделай
веб-панель `mas/dashboard` на **FastAPI + Jinja2**, работающую в одном процессе с
оркестратором.

### Что сделать

1. **Приложение** — фабрика `create_app(settings=None, orchestrator=None)`: оркестратор
   создаётся и подключается в lifespan (не при импорте), в тестах можно передать фейк.
   Запуск: `python -m mas.dashboard` (uvicorn, хост/порт из окружения, по умолчанию
   `127.0.0.1:8000`).
2. **Страницы** (серверный рендер Jinja2, без сборки фронтенда, на русском):
   - **Обзор**: агенты (id, роль, язык, статус «в сети/нет связи/останавливается»,
     обработано/ошибок, в работе, последний heartbeat); очереди JetStream — для каждого
     консьюмера `step-*`: ожидают, в обработке, повторные доставки; метрики оркестратора;
     последние запуски; если доступен автомасштабировщик (`AUTOSCALER_URL`, его
     `GET /status`) — его состояние, недоступность не ломает страницу.
   - **Запуски**: таблица с фильтром по статусу и пагинацией (единообразно `limit`/`offset`).
   - **Запуск**: шаги цепочки (агент, попытки, длительность, статус, выход в читаемом виде),
     **журнал событий запуска по времени** («кто что получил/передал») как трасса,
     ссылка «Открыть в Jaeger» (`JAEGER_UI_URL` + `/trace/<trace_id>`).
   - **Журнал**: последние события всех компонентов с фильтром по источнику и действию;
     уведомления пациентам (`notify.patient`).
   - **Ручной запуск**: форма обращения (ФИО, возраст, телефон, жалоба, желаемая
     специальность из справочника) → `start_case` → переход на страницу запуска; форма
     отзыва (id записи, пациент, оценка 1–5, текст) → `submit_feedback`; кнопка
     «Нагрузка: N демо-обращений» для демонстрации масштабирования.
3. **Хранение событий** — дашборд подписан на `events.>` и `notify.patient`, держит
   последние 2000 событий в памяти (ограниченная очередь), группирует по `run_id`.
4. **JSON API** для автообновления и проверок: `GET /api/agents`, `/api/queues`,
   `/api/runs`, `/api/runs/{id}`, `/api/events`, `POST /api/cases`, `POST /api/feedback`,
   `GET /healthz`. Ошибки валидации — 422 с понятным текстом на русском.
5. **Автообновление** — небольшой собственный JS (`static/app.js`): раз в 2–3 с
   запрашивает JSON и обновляет таблицы через `textContent`/`createElement`,
   **без `innerHTML`** с данными. Если JS отключён, страницы работают (обновление вручную).
6. **Безопасность** — middleware заголовков из ЛР №12
   (`D:\6 семестр\Методы программирования\lab12\app\main.py`, `SecurityHeadersMiddleware`):
   CSP без `unsafe-inline` (`script-src 'self'`, `style-src 'self'`), `X-Content-Type-Options`,
   `Referrer-Policy`, `frame-ancestors 'none'`. Перенеси с указанием источника в
   docstring. Формы — POST; жалоба пациента выводится только экранированной.
7. **Вид** — аккуратный, без внешних CDN: свой `static/style.css`, понятные цвета
   статусов (зелёный/жёлтый/красный + текст, не только цвет).

## Почему так

- Журнал событий запуска на странице — это то, что преподаватель назвал достаточным для
  трассировки («какой агент что получил/передал»); Jaeger — дополнительно, по ссылке.
- Без `innerHTML` и с CSP — тот же подход, что был проверен в ЛР №12 (XSS через ФИО).
- Единообразная пагинация — учтено замечание бота по ЛР №12.
