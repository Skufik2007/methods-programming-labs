# G1 — агенты на Go (задания 1, 3, 4)

Модель-генератор: Claude Sonnet 5.5 (подагент, не видит ход работы).

## Промпт

Ты — опытный Go-разработчик распределённых систем. Напиши агентов мультиагентной системы
поддержки пациентов. Контракт (субъекты NATS, форматы JSON, ключи Redis, аукцион) —
в файле `docs/ARCHITECTURE.md` репозитория `D:\6 семестр\Методы программирования\lab13`.
Прочитай его целиком: он обязателен, отступать от форматов нельзя. Если контракт
неоднозначен — выбери вариант, запиши допущение в конец своего ответа.

### Что сделать

Go-модуль в каталоге `agents/` (`module github.com/Skufik2007/methods-programming-lab13/agents`,
`go 1.27`). Зависимости: `github.com/nats-io/nats.go` (и пакет `jetstream`),
`github.com/redis/go-redis/v9`, `go.opentelemetry.io/otel` + SDK + экспортёр
`otlptracehttp`, `gopkg.in/yaml.v3`, `github.com/google/uuid`. Логи — `log/slog`.

1. **Универсальный агент** `agents/cmd/agent`: `agent -role ../roles/triage.md`. Вид агента
   (`kind`) берётся из файла роли, обработчик выбирается из реестра. Виды: `triage`,
   `booking`, `reminder`, `feedback`.
2. **Пакеты** в `agents/internal/` (имена на твоё усмотрение, но разделение такое):
   - разбор файла роли (раздел 8 контракта): разделы Markdown + YAML-блок после
     `## Параметры`; неизвестный `kind`, нет `step`, битый YAML → ошибка с понятным текстом,
     `main` выходит с кодом 2;
   - шина: подключение к NATS, идемпотентное создание потока `TASKS` и консьюмера
     `step-<step>`, цикл выборки задач с ограничением параллелизма (`concurrency` из роли),
     публикация результата `results.<run_id>`, heartbeat, события `events.<agent_id>`,
     распространение `traceparent` через заголовки NATS (W3C, `propagation.TraceContext`);
   - телеметрия: TracerProvider с OTLP/HTTP (`OTEL_EXPORTER_OTLP_ENDPOINT`, по умолчанию
     `http://localhost:4318`), имя сервиса `agent-<step>`, `OTEL_SDK_DISABLED=true`
     отключает; экспорт пакетный и не блокирует обработку;
   - хранилище Redis за интерфейсом (чтобы бизнес-логику можно было тестировать с
     miniredis или фейком);
   - расписание врача: перенеси на Go логику из
     `D:\6 семестр\Методы программирования\lab12\app\services\scheduling.py`
     (сетка от начала смены, полуоткрытые интервалы, свободные слоты, местное время
     `Europe/Moscow` через `time.LoadLocation` + `import _ "time/tzdata"`). Не копируй
     Python дословно — напиши идиоматичный Go и укажи в комментарии пакета, откуда логика;
   - по пакету на вид агента с чистой бизнес-логикой (вход → выход), отдельно от NATS.
3. **Поведение видов** — по разделам 2, 4.4, 6, 11 контракта:
   - **triage**: правила в YAML роли: ключевые фразы «красных флагов» (emergency) и
     срочности (urgent), возрастные правила (младше 1 года или 75+ → не ниже `urgent`),
     `max_wait_hours` по уровням, словарь «фраза → специальность» на случай пустой
     специальности от intake. Красные флаги ищутся и в `case.complaint`, и в
     `previous.red_flags`: LLM может добавить флаг, но не убрать. Специальность от intake
     принимается только из справочника (раздел 7), иначе `therapist`.
     `case.preferred_specialty` из справочника имеет приоритет при `routine`.
   - **booking**: врачи из YAML роли (id, ФИО, специальность, рабочие дни ISO, начало и
     конец смены, шаг слота), `min_lead_minutes` (запись не раньше чем через N минут),
     горизонт поиска. Подписка на `auction.booking` (ответ ставкой — раздел 6, формула
     cost точно по контракту; если `agent_id` в `exclude_agents` — не отвечать) и на
     `agent.<agent_id>.book` (атомарная бронь `SET NX` + запись в
     `mas:doctor:<id>:booked` и `mas:appt:<id>`; ответ — формат результата из 4.2 с
     `output` из 4.4 или `error: "slot_taken"`). Booking **не** читает поток TASKS.
   - **reminder**: смещения напоминаний из YAML (например `24h`, `2h`), канал; прошедшие
     смещения пропускаются; если пропущены все — одно напоминание «сейчас». Переменная
     `REMINDER_DEMO_DELAY` (например `20s`) для демонстрации: i-е напоминание
     отправляется через `delay·(i+1)` от момента планирования. Диспетчер раз в секунду
     забирает созревшие напоминания (`ZRANGEBYSCORE` + забор через `ZREM`, раздел 11),
     публикует `notify.patient` и событие `notified`, увеличивает `sent` в
     `mas:stats:reminder`. После рестарта всё продолжается из Redis.
   - **feedback**: `kind=schedule_survey` — опрос через `survey_delay` после конца приёма,
     хранение и отправка тем же механизмом диспетчера (`mas:surveys:due`); общий код
     диспетчера вынеси в отдельный пакет, не дублируй. `kind=analyze` — оценка 1..5
     (иначе `success=false`, не retryable), тональность по оценке и словарям из YAML,
     темы по словарю, `escalate` для негативных, `nps_bucket`: 5 → promoter, 4 → passive,
     1–3 → detractor; статистика в `mas:feedback:stats`.
4. **Общее для агентов**:
   - конфигурация из окружения: `NATS_URL` (по умолчанию `nats://localhost:4222`),
     `REDIS_URL` (`redis://localhost:6379/0`; для triage необязателен — без него счётчики
     в памяти), `AGENT_ID` (по умолчанию `<step>-<pid>`), `LOG_LEVEL`, `LOG_FILE`
     (логи JSON и в stdout, и в файл, если задан), `CLINIC_TZ`;
   - демо-сбои: `AGENT_FAIL_RATE` (0..1) — доля задач, на которые агент отвечает
     `success=false, retryable=true, error="simulated failure"`; `AGENT_SLOW_MS` — искусственная
     задержка обработки (для демонстрации очереди и масштабирования);
   - счётчики `processed`/`failed` в heartbeat и в Redis `mas:stats:<step>` (после
     рестарта продолжаются);
   - события журнала: `received` при получении задачи, `completed`/`failed` после,
     `published` при публикации результата, `bid`/`won`/`booked` у записи;
   - некорректный JSON задачи → `Term()` + событие `failed`, агент не падает;
   - graceful shutdown по SIGINT/SIGTERM (раздел 13); никаких глобальных подключений при
     импорте пакетов — всё создаётся в `main`/конструкторах;
   - время через инжектируемые часы (интерфейс или `func() time.Time`), чтобы логику
     можно было тестировать.
5. **Файлы ролей** в `roles/` (корень репозитория): `triage.md`, `booking-a.md`
   (терапевты и ЛОР, 3 врача), `booking-b.md` (кардиолог, невролог, офтальмолог,
   дерматолог, травматолог и ещё один терапевт), `reminder.md`, `feedback.md`.
   Разделы — по разделу 8 контракта, текст на русском, параметры правдоподобные для
   поликлиники.

### Ограничения

- Тесты не пиши — их напишет другая модель. Но код должен быть тестируемым: бизнес-логика
  без NATS/Redis, зависимости через интерфейсы.
- Go установлен в `D:\dev\go\bin` (добавь в PATH: `export PATH="/d/dev/go/bin:$PATH"` в
  Bash). Перед завершением выполни в `agents/`: `go mod tidy`, `go build ./...`,
  `go vet ./...` — всё должно проходить. Сеть нестабильна: при сбое скачивания модулей
  повтори команду.
- Не трогай файлы вне `agents/` и `roles/`. Не делай git-коммитов.
- Комментарии — на русском, только к неочевидному (почему, а не что).

## Почему так

- Контракт вынесен в `docs/ARCHITECTURE.md`, чтобы Go- и Python-генераторы работали
  параллельно и не разошлись в форматах.
- Явно запрещено LLM снимать красные флаги: безопасность пациента не должна зависеть от
  модели.
- Переиспользование ЛР №12 — через перенос логики расписания с указанием источника, а не
  копированием.
