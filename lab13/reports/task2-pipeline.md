# Задание 2. Цепочки задач (pipeline)

**Требование:** последовательная обработка задачи несколькими агентами: результат агента A
идёт в очередь агента B и т. д.; оркестратор управляет цепочкой.

## Что сделано

Оркестратор на Python (asyncio + nats-py, [`mas/orchestrator`](../mas/orchestrator/orchestrator.py))
ведёт обращение пациента по цепочке:

```
Анализ обращения (LLM) → Триаж → Запись (аукцион) → Напоминание → Опрос после приёма
```

- Шаги отправляются задачами в поток JetStream `TASKS` (`tasks.<шаг>`). Агенты одного шага
  читают общий durable-консьюмер `step-<шаг>`.
- Выход шага *n* целиком передаётся во вход шага *n+1* (`payload.previous`). Исходное
  обращение передаётся как `payload.case`, а выходы всех прошлых шагов — как `payload.history`.
  `history` понадобился, потому что напоминанию нужен выход записи, а опросу — время конца приёма.
- Результаты агенты публикуют в `results.<run_id>`. Оркестратор сопоставляет их с ожидаемой
  попыткой по `task_id`, а устаревшие ответы игнорирует.
- Управление цепочкой:
  - таймаут на шаг (15 с, для LLM 90 с);
  - до 3 попыток при таймауте или временной ошибке;
  - задача попытки, завершившейся таймаутом, удаляется из потока;
  - `emergency` на триаже останавливает цепочку с рекомендацией «Вызовите скорую: 103»;
  - если свободных врачей нет, плановому обращению окно поиска расширяется, срочное
    получает рекомендацию (раздел 6 контракта).
- Вторая цепочка — отзыв пациента: `Анализ отзыва (Go) → [если негативный] Ответ пациенту (LLM)`.

## Проверка

- Локально, 5 демо-обращений (`python -m mas.orchestrator demo --cases 5`): 4 `completed`,
  1 `stopped` (боль в груди → «Вызовите скорую: 103»).
- Страница запуска на дашборде: шаги, агент, попытки, выход каждого шага и журнал событий —
  [img/dashboard-run-steps.jpg](img/dashboard-run-steps.jpg), [img/dashboard-run-journal.jpg](img/dashboard-run-journal.jpg).
- Цепочка отзыва: оценка 2 («ждал 40 минут, грубо») → `negative`, темы «ожидание»,
  «персонал» → LLM написала ответ пациенту. Оценка 5 → `positive`, шаг ответа пропущен.
- CI (Docker Compose, e2e): 5 обращений с ожидаемыми статусами, 40 обращений под нагрузкой —
  все `completed`.
- Тесты: `tests/unit/test_orchestrator_chain.py` (цепочка, `previous`, повторы, таймауты,
  `emergency`, устаревшие результаты, отзыв) на фейковой шине [`tests/fakes.py`](../tests/fakes.py).
