# Задание 5. Динамическое масштабирование

**Требование:** автоматически запускать дополнительные экземпляры агента при высокой
нагрузке (например, длина очереди > N) через Docker API или оркестратор. Преподаватель:
достаточно показать запуск дополнительных экземпляров по длине очереди.

## Что сделано

Автомасштабировщик на Go ([`agents/cmd/autoscaler`](../agents/cmd/autoscaler),
[`internal/autoscale`](../agents/internal/autoscale)):

- раз в 2 с читает `ConsumerInfo` консьюмера `step-<шаг>`; backlog = `num_pending +
  num_ack_pending`;
- политика — чистая функция `Desired`: `clamp(ceil(backlog / per_instance), min, max)`.
  Рост сразу на нужное число, уменьшение — только после `cooldown` (30 с) без роста очереди.
  `min` экземпляров статические (из compose или скрипта), автомасштабировщик управляет
  только добавочными;
- бэкенды:
  - **`docker`** — Docker Engine API напрямую по `/var/run/docker.sock`, без SDK: создать,
    запустить, остановить и удалить контейнер из образа агента в сети compose. Метки
    `mas.autoscaler`, `mas.step`; свои контейнеры подхватываются после рестарта;
  - **`exec`** — локальные процессы, потому что Docker на машине нет;
- события `scaled_up` / `scaled_down` в журнал, спаны `autoscaler.reconcile`,
  `GET /status` для дашборда.

Балансировка: все экземпляры шага читают один durable-консьюмер JetStream, и сервер
раздаёт задачи между ними.

## Проверка

**Локально (бэкенд `exec`, [`deploy/autoscaler.local.yaml`](../deploy/autoscaler.local.yaml):
`per_instance: 5`, `max: 3`, `cooldown: 30s`).**
- Триаж замедлен через `AGENT_SLOW_MS=3000`. В очереди `step-triage` 121 задача.
- Лог автомасштабировщика:
  ```
  "msg":"scaled_up",  "step":"triage","backlog":121,"was":1,"now":3
  "msg":"scaled_down","step":"triage","backlog":9,  "was":3,"now":2
  "msg":"scaled_down","step":"triage","backlog":5,  "was":2,"now":1
  ```
- Запущены `triage-auto-1` и `triage-auto-2`. После разбора очереди и cooldown остался
  1 экземпляр.

**CI (бэкенд `docker`, Docker Compose).**
- Нагрузка: 40 обращений, `TRIAGE_SLOW_MS=800`.
- e2e:
  - «автомасштабировщик: /status показывает больше одного экземпляра триажа — макс.
    очередь 36, макс. экземпляров 3»;
  - «в журнале дашборда есть событие scaled_up»;
  - «обращения нагрузки обработаны без провалов — completed: 40».

## Находки при проверке

| № | Что было | Исправление |
|---|---|---|
| 5 | Backlog 121 на 40 обращений: задачи проваленных попыток оставались в очереди, и автомасштабировщик поднимал экземпляры под «мёртвую» нагрузку | Оркестратор удаляет задачу попытки, завершившейся таймаутом (`discard_task`) |
