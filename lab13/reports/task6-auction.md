# Задание 6. Аукционное распределение задач

**Требование:** агенты «торгуются» за задачу: каждый оценивает свою способность выполнить
её (cost, skill, availability), оркестратор выбирает агента с наименьшей стоимостью.
Стоимость определяем сами.

## Модель стоимости

Агентов записи два: `booking-a` (терапевты и ЛОР) и `booking-b` (узкие специалисты и ещё
один терапевт). На запрос `auction.booking` каждый отвечает ставкой по своему **лучшему**
врачу:

| Параметр | Как считается |
|---|---|
| `skill` | 1.0 — специальность совпадает; 0.5 — терапевт вместо узкого специалиста, только при плановом обращении; иначе 0 и ставка `eligible=false` |
| `availability` | `1 − wait_h / max_wait_hours`, где `wait_h` — часы до ближайшего свободного слота. Слот позже окна → `eligible=false` |
| `load` | доля занятых слотов врача на 7 суток |
| **`cost`** | **`0.5·(1 − availability) + 0.3·load + 0.2·(1 − skill)`**, меньше — лучше |

- **Вес ожидания (0.5) больше всех.** Для пациента главное — как скоро его примут.
- **Нагрузка (0.3) распределяет пациентов.** Без неё самый свободный врач собирал бы всех
  пациентов подряд.
- **Замена специалиста терапевтом (0.2) — запасной вариант.** Её разрешаем только при
  плановом обращении: срочному пациенту нужен профильный врач.

Оркестратор собирает ставки 500 мс (свой inbox, потому что `request()` в nats-py ждёт
только один ответ). Победитель — минимальный `cost`; при равенстве — более ранний слот,
затем `agent_id`. Победителю уходит `agent.<id>.book`, бронь атомарная (`SET NX`).

Правила выбора — чистые функции, проверяемые тестами: `bid_cost`, `choose_winner`,
`parse_bids` в [`mas/orchestrator/auction.py`](../mas/orchestrator/auction.py), `Cost`/`Bid`
в [`internal/booking`](../agents/internal/booking/booking.go).

## Проверка

Фрагмент журнала событий запуска (локально, жалоба на ухо → ЛОР):

```
booking-b-1  bid   doctor=d-therapist-3 cost=0.109
booking-a-1  bid   doctor=d-therapist-1 cost=0.110
orchestrator won   booking-b-1 doctor=d-therapist-3 cost=0.109 bids=2
booking-b-1  failed slot_taken                      ← параллельный аукцион успел раньше
orchestrator retry slot_taken; round=2
orchestrator won   booking-a-1 doctor=d-therapist-1 cost=0.110 bids=2
booking-a-1  booked doctor=d-therapist-1 slot=2026-10-13T08:00:00Z
```

Этот прогон был до находки №12. После неё занятый слот заменяется следующим слотом того
же врача, и раунды почти не нужны.

## Находки при проверке

| № | Что было | Исправление |
|---|---|---|
| 7 | На дашборде у записи «ставок 0, стоимость 0»: агент кладёт нули, оркестратор не перезаписывал их через `setdefault` | Итоги аукциона записывает оркестратор |
| 11 | Ставка со слотом без часового пояса при равной стоимости роняла `choose_winner` (TypeError naive/aware) и весь запуск. Нашёл генератор тестов | Такие ставки пропускаются |
| 12 | При 40 одновременных обращениях все аукционы выбирали один слот, 21 запуск провалился после 3 раундов | Агент занимает ближайший свободный слот того же врача в окне пациента |
| 15 | Под `-race` в CI агент записи не успевал подписаться на `auction.booking` до первого аукциона, и одна ставка терялась | `Subscribe` дожидается регистрации подписки на сервере (`Flush`) |
