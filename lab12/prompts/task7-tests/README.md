# Задание 7. Система промптов для генерации тестов

Цель — покрытие кода приложения не ниже 90% (coverage.py, с учётом ветвлений) при
тестах, которые проверяют поведение, а не просто «проходят строки».

## Из чего состоит система

| Файл | Роль |
|------|------|
| [`00-system.md`](00-system.md) | Общая часть, которая добавляется к каждому запросу: роль, стек, правила хороших тестов, фикстуры проекта, формат ответа |
| [`01-unit.md`](01-unit.md) | Шаблон для чистых функций и валидаторов: таблица граничных значений, `pytest.mark.parametrize` |
| [`02-api.md`](02-api.md) | Шаблон для HTTP-слоя: матрица «роль × действие → код ответа», чужие объекты (404), ошибки валидации |
| [`03-async.md`](03-async.md) | Шаблон для асинхронного кода: конкурентные запросы, гонки, транзакции, «замороженное» время |
| [`04-gap.md`](04-gap.md) | Шаблон добивания: на вход подаётся отчёт `coverage report -m` с непокрытыми строками, на выход — тесты только на них |

Готовый запрос собирается так: `00-system` + один шаблон с подставленными
`{{модули}}` и `{{фокус}}`. Собранные запросы и ответы модели лежат в `runs/`
(G1…G4 — первый проход по модулям, G5 и далее — добивание по отчёту покрытия).

## Процесс

1. Первый проход: четыре независимых запроса по группам модулей (см. `runs/`).
   Модель видит код приложения и `tests/conftest.py`, но не видит существующих тестов,
   чтобы не копировать их.
2. Код тестов извлекается из ответа скриптом `prompts/tools/extract.py` и коммитится
   без правок.
3. Прогон: `pytest --cov --cov-branch`. Упавшие тесты разбираются вручную: ошибка в
   тесте исправляется, ошибка в приложении документируется в
   `reports/code-review.md` и исправляется отдельным коммитом.
4. Добивание: непокрытые строки из `coverage report -m` подставляются в шаблон
   `04-gap.md`, и шаг повторяется, пока покрытие не достигнет 90%.

Итоговый отчёт с цифрами по шагам — [`reports/coverage.md`](../../reports/coverage.md).
