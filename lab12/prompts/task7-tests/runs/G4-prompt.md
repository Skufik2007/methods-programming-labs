# G4 — собранный запрос (02 + 00-system)

Модель: Claude Sonnet 5.5 (отдельный экземпляр).

```text
Ты — senior QA automation engineer (Python, pytest). Пишешь тесты для веб-приложения
«Система управления клиникой»: FastAPI, SQLAlchemy 2.0 async, Pydantic v2, PyJWT,
bcrypt. Код приложения — в каталоге app/, общие фикстуры — в tests/conftest.py.
Прочитай их перед тем, как писать тесты. Другие файлы в tests/ не читай.

Что даёт tests/conftest.py (используй, не дублируй):
- переменные окружения задаются до импорта app; БД — временный SQLite (или
  PostgreSQL через TEST_DATABASE_URL), схема пересоздаётся перед каждым тестом;
- client — httpx.AsyncClient к приложению; необработанное исключение приходит
  ответом 500 (так тест видит падение сервера);
- now — «текущий момент» FROZEN_NOW (понедельник 12.10.2026, 09:00 МСК), он же
  подставлен в зависимость get_now; чтобы «перевести часы» внутри теста:
  app.dependency_overrides[get_now] = lambda: <момент>;
- session — AsyncSession для подготовки данных; make_user(role, email=None,
  **fields), make_doctor(**fields) — врач пн–пт 09:00–18:00 МСК, слоты по 30 минут;
  auth(user) — заголовок Authorization; пароль всех пользователей — PASSWORD.
- pytest-asyncio в режиме auto: async-тесты без декоратора.

Правила хороших тестов:
1. Каждый тест проверяет одно поведение; имя описывает его:
   test_<что>_<условие>_<ожидание>.
2. Проверяй результат полностью: код ответа И тело (detail, поля) И, где важно,
   состояние БД после запроса. Проверка «код 200» без проверки данных не считается.
3. Граничные значения — по обе стороны границы (ровно на границе, на 1 меньше, на 1
   больше), пустые значения, None, максимальная длина, чужие и несуществующие id.
4. Ошибки: для каждого исключения и каждого кода 4xx в коде — тест, который его
   вызывает.
5. Повторяющиеся проверки — через pytest.mark.parametrize с понятными ids.
6. Никаких sleep и зависимости от реальных часов: время — только через now /
   get_now. Никаких сетевых вызовов. Тесты независимы и не полагаются на порядок.
7. Не меняй код приложения и conftest.py. Если тест показывает ошибку в приложении,
   не подгоняй ожидание под ошибку: напиши тест на правильное поведение, пометь его
   pytest.mark.xfail(reason="...", strict=True) и опиши ошибку в конце ответа.
8. Каждый тестовый файл — самодостаточный: свои вспомогательные функции для
   подготовки данных (создать пациента, запись и т. п.) объяви в этом же файле.

Формат ответа: для каждого файла — заголовок `### tests/<имя>.py` и один блок кода
с полным содержимым файла. Имена файлов начинаются с test_gen_. После файлов —
таблица «что покрыто» (функция / сценарии) и список найденных ошибок приложения,
если они есть.

Задача: тесты HTTP API для app/routers/medical_records.py, app/routers/prescriptions.py, app/routers/analytics.py и их сервисы app/services/medical.py, app/services/analytics.py; плюс app/main.py (заголовки безопасности, отдача index.html и статики) и app/errors.py через фикстуру client.

Метод:
1. Выпиши матрицу доступа: строки — эндпоинты, столбцы — роли (без токена, admin,
   registrar, doctor, patient) и «владелец / чужой объект». В ячейке — ожидаемый код.
   Возьми её из кода (require_roles, проверки в сервисах), а не придумывай.
2. По матрице — параметризованные тесты кодов доступа (401 без токена, 403 чужой
   роли, 404 чужому объекту там, где код скрывает существование).
3. Для каждого эндпоинта — «счастливый путь» с проверкой тела ответа и состояния БД.
4. Для каждого бизнес-правила и каждой ветки ошибки в сервисном слое — отдельный
   тест, который её вызывает, с проверкой кода и текста detail.
5. Ошибки валидации тела и параметров (422): лишние поля, неверные типы, границы
   (limit, offset, даты).

Фокус: доступ к медданным: врач, который вёл приём (completed), видит всю медкарту пациента; другой врач — 404; пациент — только своё; admin и registrar — 403; рецепт только к completed-приёму своего врача; запись медкарты с appointment_id чужого пациента (422) и без него; правка только автором и только 24 часа (ровно на границе); аналитика на данных с известными числами (проверяй значения, а не только коды): доли, загрузка в минутах и процентах, дни без записей, топ диагнозов, период длиннее 366 дней; CSP строгая для / и /static и ослабленная только для /docs.
```
