# E1 — расширение VS Code «Объясни этот код»

Модель: Claude Sonnet 5.5 (отдельный экземпляр, без доступа к проекту).

Почему так: расширение должно работать с локальной моделью из задания 3 (Ollama),
поэтому API зафиксировано заранее (`/api/chat` с потоковой выдачей) и модель не
выбирает облачный сервис. Веб-панель VS Code — частый источник XSS: ответ LLM
приходит в виде Markdown, и вставить его через `innerHTML` проще всего. Поэтому в
промпте явно заданы CSP с nonce и вывод текста без интерпретации HTML. Логика без
VS Code API (сборка промпта, разбор потока NDJSON) вынесена отдельно, чтобы её можно
было протестировать встроенным `node:test`, не запуская редактор.

## Текст промпта

```text
Ты — senior TypeScript-разработчик расширений VS Code. Напиши расширение
«Clinic AI: Explain Code» (учебный проект, publisher "chetverikov-lab").

Функции:
1. Команда clinicAi.explainCode «Объясни этот код»: горячая клавиша Ctrl+Alt+E
   (Cmd+Alt+E на macOS), пункт контекстного меню редактора и кнопка в editor/title
   (видна, когда есть выделение). Берёт выделенный код; если выделения нет —
   текущую строку и по 10 строк вокруг. Код длиннее 12 000 символов обрезается с
   предупреждением.
2. Ответ показывается в панели (WebviewPanel рядом с редактором) по мере генерации:
   потоковый вывод из Ollama /api/chat (stream: true, ответ — NDJSON, по объекту на
   строку, поле message.content, последний объект с done: true). Кнопки «Стоп»
   (AbortController) и «Копировать». Повторный вызов команды переиспользует панель.
3. Свой промпт: системный промпт по умолчанию — объяснение на русском языке по
   структуре «Что делает код → Как работает (по шагам) → Неочевидные места и
   возможные ошибки → Как улучшить»; учитывает язык файла (languageId) и имя файла.
   Пользователь может заменить его настройкой clinicAi.systemPrompt.
4. Настройки: clinicAi.ollamaUrl (по умолчанию http://127.0.0.1:11434),
   clinicAi.model (по умолчанию qwen2.5-coder:3b), clinicAi.systemPrompt,
   clinicAi.temperature (0..1, по умолчанию 0.2).
5. Понятные ошибки: Ollama не запущен (ECONNREFUSED / fetch failed) — сообщение с
   командой запуска; модели нет (404) — сообщение с командой ollama pull.

Безопасность панели: Content-Security-Policy с nonce (default-src 'none'; скрипты
только с nonce; стили — из файла расширения через asWebviewUri), enableScripts
только с localResourceRoots = каталог media; текст модели выводится через
textContent (Markdown показывается как моноширинный текст с переносами, без
интерпретации HTML). Сообщения webview ↔ расширение — postMessage с проверкой типа.

Структура:
- package.json (engines.vscode ^1.90.0, main: ./out/extension.js, contributes:
  commands, keybindings, menus, configuration; scripts: compile, watch, test,
  package через @vscode/vsce);
- tsconfig.json (strict), .vscodeignore;
- src/extension.ts — активация, команда, панель;
- src/ollama.ts — потоковый клиент /api/chat на встроенном fetch (Node 18+),
  разбор NDJSON по чанкам (строка может прийти частями);
- src/prompt.ts — сборка сообщений: системный промпт + код в блоке с языком,
  обрезка, выбор контекста вокруг курсора (чистые функции без vscode);
- media/panel.js, media/panel.css — скрипт и стили панели;
- test/*.test.ts — тесты на node:test для prompt.ts и разбора NDJSON в ollama.ts
  (без запуска VS Code): разбиение строк между чанками, пустые строки, ошибка в
  потоке ({"error": ...}), done, обрезка длинного кода, контекст у начала и конца
  файла;
- README.md — установка (.vsix), настройка, использование, как запустить тесты.

Без внешних зависимостей во время выполнения (только devDependencies: typescript,
@types/vscode, @types/node, @vscode/vsce). Код с комментариями там, где логика
неочевидна.

Формат ответа: для каждого файла — заголовок `### vscode-extension/<путь>` и один
блок кода с полным содержимым файла. После файлов — допущения и что проверить на
ревью.
```
