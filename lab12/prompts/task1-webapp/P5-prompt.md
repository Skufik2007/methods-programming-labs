# P5 — веб-интерфейс и админ-панель

Модель: Claude Sonnet 5.5 (отдельный экземпляр). Доступ: только чтение `app/`.

Почему так: API готово и проверено, но пользоваться им можно только через Swagger.
Задание требует веб-приложение с админ-панелью, поэтому нужен интерфейс. Сборка
фронтенда (npm, бандлер) для учебного проекта лишняя, поэтому заказан ванильный
JS, который отдаёт сам FastAPI. Основной риск такого кода — XSS, а в данных есть ФИО
и тексты медкарт. Поэтому в промпте явно запрещён `innerHTML` с данными, внешние
CDN запрещены, а политика CSP задана заголовком, что позволяет закрыть inline-скрипты.

## Текст промпта

```text
Ты — senior full-stack разработчик. Проект «Система управления клиникой»: бэкенд на
FastAPI готов (прочитай каталог app/ — роутеры, схемы, правила доступа). Нужен
веб-интерфейс, который работает с этим API.

Ограничения:
- без сборки и без npm: app/static/index.html, app/static/app.css, app/static/app.js
  (ES2020, модули не обязательны), отдаются самим FastAPI;
- никаких внешних ресурсов (CDN, шрифты, аналитика) — всё локально;
- данные из API вставляются в DOM только через textContent / createElement;
  innerHTML с данными запрещён (в данных есть ФИО и тексты медкарт — защита от XSS);
- в index.html нет inline-скриптов и inline-стилей, обработчики — через
  addEventListener;
- токен хранится в sessionStorage, не в localStorage; при 401 — выход на экран входа;
- интерфейс на русском языке; время показывается в часовом поясе клиники
  (Europe/Moscow), на сервер уходит ISO 8601 с часовым поясом.

Изменения бэкенда (app/main.py приведи целиком):
- раздача статики: GET / отдаёт index.html, /static — остальные файлы;
- middleware с заголовками безопасности для всех ответов: Content-Security-Policy
  (default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:;
  frame-ancestors 'none'), X-Content-Type-Options: nosniff, Referrer-Policy:
  no-referrer. Swagger UI (/docs) грузит скрипты с CDN — для /docs и /redoc CSP
  должна оставаться рабочей (ослабь её только для этих путей и объясни).

Экраны по ролям (одна страница, разделы переключаются без перезагрузки):
- вход и самостоятельная регистрация пациента;
- пациент: мои записи (отмена), новая запись — выбор врача (специальность), даты и
  свободного слота из /api/doctors/{id}/slots; профиль; моя медкарта и рецепты;
- врач: расписание на выбранный день, отметки «приём состоялся» / «неявка», для
  завершённого приёма — добавить диагноз (МКБ-10) и рецепт; медкарта пациента;
- регистратор: поиск и создание пациентов, запись пациента к врачу, отмена и
  перенос записей;
- администратор (админ-панель): пользователи (создание, смена роли, блокировка),
  профили врачей и графики, и дашборд аналитики за период — сводка по статусам,
  загрузка врачей, записи по дням, частые диагнозы. Графики — собственный простой
  SVG (столбчатые диаграммы), без библиотек.
- ошибки API (detail — строка или список ошибок валидации) показываются понятным
  сообщением рядом с формой.

Требования: аккуратный адаптивный вид (работает на ширине 360 px), семантическая
вёрстка, доступность (label у полей, фокус видим); код JS разбит на небольшие
функции с комментариями. Тесты не пиши.

Формат ответа: для каждого файла — заголовок `### путь/к/файлу` и один блок кода с
полным содержимым файла. После файлов — короткий список допущений и отдельный список
мест, которые стоит особенно внимательно проверить на ревью.
```
