| Ответы P2–P5 содержали файлы, которые `extract.py` не извлёк: пояснение между заголовком и блоком кода, `Dockerfile` без расширения | Доработан скрипт извлечения (отдельный коммит), ответы модели не менялись |

| Coverage показывал 63% → 79% при более чем 2000 тестах | Ошибка измерения, а не тестов: SQLAlchemy async работает через greenlet, coverage терял трассировку. Добавлено `concurrency = ["greenlet", "thread"]` — реальное покрытие 98% |
| Локальная qwen 3b зацикливалась: T2 генерировала больше 15 минут, C1 упиралась в лимит токенов | Лимит `num_predict`, для C1 третья итерация с `repeat_penalty`. Результат честно записан как отказ модели |
| Облачная сессия на T3 (задание 3) прервалась по лимиту запросов | Ответ успел сохраниться. Время не зафиксировано, это отмечено в отчёте |

## Задание 2. Code review

Агент по моему поручению проверял каждый ответ модели. Проверка шла так:
1. запуск и дымовые сценарии через HTTP;
2. прогон на временном PostgreSQL;
3. ruff;
4. ручное чтение кода.

Каждая находка в приложении подтверждена тестом, который до исправления падал.
Находка в расширении проверена его тестами и сборкой, находка в ИИ-ревью — повторным
запуском на демо-PR. Итог — 9 реальных проблем в
[`reports/code-review.md`](reports/code-review.md).

Кроме девяти находок в отчёте, при проверке нашлось ещё одно место. Скрипт ИИ-ревью
вызывал `urlopen` с адресом из окружения без проверки схемы. Это исправлено отдельным
коммитом.
