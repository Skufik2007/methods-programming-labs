- общий системный промпт;
- шаблоны для четырёх видов кода: чистые функции, HTTP и права, асинхронность,

Собранные запросы G1–G4 и ответы модели лежат в
[`prompts/task7-tests/runs`](../prompts/task7-tests/runs). Тесты из ответов
извлечены и закоммичены без правок. Потом к ним применён только `ruff format`, это
отдельный стилевой коммит.

### Сбой измерения, который пришлось найти

Первые замеры показывали 63% и 79% при тысячах тестов. Причём непокрытыми
оказывались строки, которые тесты заведомо выполняют: например `list_free_slots` при
сотне тестов слотов. Причина — в инструменте:

- SQLAlchemy в асинхронном режиме выполняет запросы через `greenlet`;
- без `concurrency = ["greenlet", "thread"]` coverage после переключения greenlet
  теряет трассировку и не засчитывает дальнейшие строки.

После исправления настройки в `pyproject.toml` те же тесты дали 98%. Все цифры в
таблице выше получены уже с правильной настройкой.

## Что осталось непокрытым и почему

| Где | Строки | Почему |
|---|---|---|
| `routers/auth.py` | 102–106 | гонка при регистрации: два одинаковых запроса проходят предварительную проверку одновременно, срабатывает уникальный индекс; через HTTP-клиент тестов не воспроизводится |
| `main.py` | 67–68, 87–90 | `lifespan` (освобождение пула при остановке) и ветка ASGI-middleware для не-HTTP событий: тестовый клиент не запускает lifespan |
| `db.py` | 64 | `dispose_engine` вызывается только из lifespan |
| `models.py` | 74, 76, 81, 84 | ветки `UTCDateTime`: значение `None`, отказ naive-времени (до него не доходит — схемы отсекают раньше) и aware-время из PostgreSQL (в SQLite-прогоне не исполняется) |
| `services/*` | по 1–4 строки | защитный код (повторная проверка роли, которую уже отсекает `require_roles` в роуте) и ветки только для PostgreSQL (`_lock_row` в SQLite-прогоне сразу выходит) |

## Качество тестов, а не только процент

Системный промпт требует проверять не только код ответа, но и тело с состоянием БД;
граничные значения — с обеих сторон; ошибки — каждую. Что из этого получилось:

- **Параметризация.** 257 декораторов `pytest.mark.parametrize`, у наборов понятные
  `ids`.
- **Время.** Проверяется ровно на границах окон: за 2 часа до приёма, 24 часа после
  записи в медкарту. Часы «переводятся» только через `get_now`, `sleep` нет.
- **Конкурентность.** Одновременные записи на одно и пересекающееся время,
  одновременные отмена и завершение. Проверяется итоговое число строк в БД, а не
  только коды ответов.
- **Аналитика.** Значения сверяются на данных с заранее известными числами: доли,
  минуты, проценты.

**Ошибок приложения генераторы не нашли** (тестов с `xfail` нет). К этому моменту
находки ревью в приложении (№1–7) уже были исправлены, и на них есть регрессионные тесты. Модели
отметили спорные места, которые не являются ошибками:
- проверка даты рождения использует реальные часы, а не `get_now`;
- `PATCH {}` к несуществующей записи медкарты даёт 422, а не 404;
- ослабленная CSP выдаётся и `/docs/oauth2-redirect`.
