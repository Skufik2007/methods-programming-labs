# Задание 3. Локальная LLM (Ollama + Continue.dev) против облачной модели

## Окружение

| Компонент | Значение |
|---|---|
| Локальный сервер | Ollama 0.40.2 (Windows), модели в `D:\dev\ollama\models` |
| Локальные модели | `qwen2.5-coder:3b` (Q4_K_M, 1,9 ГБ) для чата; `qwen2.5-coder:1.5b` для автодополнения |
| Железо | NVIDIA GeForce RTX 3050 Laptop, 4 ГБ видеопамяти: модель 3b целиком в видеопамяти, 7b бы не поместилась |
| IDE | VS Code 1.101 + Continue.dev 2.0.0, конфигурация [`tooling/continue/config.yaml`](../tooling/continue/config.yaml) |
| Облачная модель | Claude Sonnet 5.5 (отдельный экземпляр, без инструментов: отвечает как в чате) |

Распределение моделей в Continue.dev:
- 3b отвечает за чат, правки (`edit`) и применение изменений (`apply`);
- 1.5b отвечает за автодополнение, где задержка важнее качества.

В конфигурации также заданы:
- правила проекта: язык ответов, стек, запрет секретов в коде и `innerHTML`;
- свой промпт `/explain-clinic`.

## Методика

Обеим моделям отправлен один и тот же текст запроса:
[`comparison/task3/prompts`](../comparison/task3/prompts). Ответы сохранены без правок
в [`comparison/task3/answers`](../comparison/task3/answers). Оценивает их скрипт
[`harness.py`](../comparison/task3/harness.py), а не я.

| Задача | Что проверяет | Как оценивается точность |
|---|---|---|
| T1. Проверка СНИЛС | генерация кода по спецификации с вычислениями | 23 скрытые проверки: форматы, все ветви контрольной суммы (сумма < 100, 100, 101, > 101, остаток 100), номера ≤ 001-001-998 |
| T2. Поиск ошибки | понимание кода | исправленная функция прогоняется на 6 сценариях; отдельно — сколько из 3 заложенных ошибок названо: нестрогие `<=`, `return True` внутри цикла, `None` при пустом списке |
| T3. Генерация тестов | тестирование | тесты должны проходить на правильной реализации; точность — доля «убитых» мутантов, 6 испорченных версий функции |

**Релевантность** — моя оценка от 1 до 5: отвечает ли модель на заданный вопрос, нет
ли лишнего и неверного в пояснениях.

**Скорость.** Для локальной модели время и токены/с дают метрики Ollama. Для облачной —
время запроса по данным среды.

### Разбор ответов локальной модели

**T1.**
- Модель удаляет пробелы, но не дефисы, поэтому основной формат `112-233-445 95`
  отвергается.
- Любой номер с контрольным числом `00` считается верным без проверки.
- Правило «номера ≤ 001-001-998 не проверяются» не реализовано.

Веса цифр при этом посчитаны правильно.

**T2.**
- Исправленный код верный.
- Названы две ошибки из трёх. Про пустой список прямо не сказано: он исправился
  побочно, вместе с `return True`.
- Пояснение противоречит коду: «удалён лишний `return True` в конце функции», хотя в
  исправленной версии он есть и нужен. Это пример галлюцинации в объяснении при
  правильном коде (см. задание 8).

**T3.**
- Ожидаемые значения в тестах посчитаны неверно: например, `assert 0 == 480` для
  одного рабочего дня.
- Тесты вырождаются в повторы с растущими именами вида
  `test_available_minutes_no_work_days_in_period_and_both_and_both`.

**Зацикливание.** При первом прогоне без лимита длины ответа модель на T2 зациклилась
и генерировала больше 15 минут. После этого всем запросам к локальной модели задан
`num_predict: 2048`. Прерванный прогон сохранён в `answers/qwen2.5-coder-3b/run1-interrupted`.

## Выводы

1. **Скорость.** Локальная модель отвечает в 1,5–3 раза быстрее на коротких задачах
   (69 токенов/с на ноутбучной видеокарте) и работает без сети. Код и данные не
   покидают машину, что важно для медицинской системы с персональными данными.
2. **Точность.** У 3B-модели она заметно ниже на всех трёх задачах. Модель справляется
   с локальным пониманием кода (T2), но ошибается в вычислениях по спецификации (T1)
   и не держит длинный структурированный ответ (T3, а также задача C1 из задания 6).
3. **Релевантность.** Облачная модель отвечает строго на вопрос и замечает то, что не
   спрашивали, но стоит учесть (`start >= end` в T2). Локальная добавляет пояснения,
   противоречащие её же коду.
4. **Практический вывод для проекта.** Локальная модель через Continue.dev годится
   там, где ответ проверяется сразу и дёшево:
   - автодополнение (модель 1.5b);
   - объяснение кода (расширение из задания 5);
   - быстрые правки небольших фрагментов.

   Генерацию логики, тестов и ревью стоит отдавать облачной модели и всё равно
   проверять тестами.
